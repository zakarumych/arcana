## Project model and present capability

[ROADMAP.md](ROADMAP.md) contains the proposed delivery milestones and their
completion criteria. It is planning guidance; this document records implemented
contracts and validation evidence.

Arcana is a Rust microengine built around dynamically loaded plugins. The runtime facade reexports small engine crates and selected external dependencies. Plugins contribute ECS systems, input filters, rendering jobs, importers, and related registrations. A project manifest selects engine and plugin dependencies; generated Rust crates build a project-specific editor executable and plugin library. The editor owns project state, plugin loading, simulation instances, and native UI.

The repository contains both implemented infrastructure and unfinished product integration. The editor toolbox supplies Plugins, Systems, Filters, Render, Simulation, and Assets tools. Simulation tools view one shared runtime and control its speed and reset. Assets tools share the project asset store and catalog, with source browsing, import configuration, name/fuzzy search, and persistent tags. Scene authoring, per-tool Play/Stop, and visual scripting sources are outside the compiled module tree; full Inspector integration, scene file persistence, and parts of the value/viewport editors remain unfinished. The high-level `README.md` describes broader intent, including capabilities not presently wired up.

Main dependency direction:

```text
launcher -> project + intern + error
                     |
                     +-> generates project/crates/{ed,plugins,game}

arcana-ed -> arcana facade -> engine subsystem crates
plugins  -> arcana facade -> registration crates / ECS / GPU APIs

editor plugin manager -> Cargo-built plugins dylib -> exported plugin metadata
editor instance       -> World + Scheduler + Flows + WorkGraph
editor UI             -> egui + winit + mev
```

There are two distinct notions of project: `engine/project::Project` handles the manifest/build workspace; `ed/src/project.rs::Project` combines that with editable engine configuration and editor-local persistence. There are likewise separate asset loading/building and source importing/storage layers.

- Root dependencies include sibling paths for `athena`, `edict` and `edict/proc-lib`, `egui-probe`, `egui-snarl`, and `mev`. ## Project manifests, generation, and launcher

`engine/project/src/lib.rs::Project` owns a `ProjectManifest` and its manifest path. `Project::load` accepts an actual `.arcana` **file**, makes its path absolute, and reads TOML; it rejects directories. `root_path` is the manifest's parent. `Project::new` creates `<name>.arcana`; `sync` overwrites that manifest. External-change detection is not implemented. `is_in_cargo_workspace` exists as a helper but is not called by the inspected project creation path.

`manifest.rs::ProjectManifest` contains only `name: Ident`, `engine: Dependency`, and `plugins: Vec<Plugin>` (empty by default). Systems, render graphs, and enabled-plugin state belong to editor persistence, not this TOML structure.

`dependency.rs::Dependency` is an untagged version string / `{ git, branch? }` / `{ path }` union. Paths are UTF-8 Camino paths, with home expansion on deserialization. `make_relative` uses the current directory as the old base; `make_relative_from` takes an explicit old base. Preserve the distinction when rebasing generated dependencies. `validate_engine_path` expects the **arcana package** (`engine/arcana` or its Cargo.toml), not the repository's workspace manifest.

`plugin.rs::Plugin` stores manifest name, description, dependency, and a computed Rust identifier that replaces hyphens with underscores. The identifier is not serialized. `open_local` reads package metadata; inherited descriptions currently warn and become empty. `Project::add_plugin` rejects duplicate names, rebases local dependencies, and does not save automatically.

### Generated files are outputs

`engine/project/src/generator.rs::init_workspace` writes `<project>/crates/` with `ed`, `plugins`, and `game` packages, a nightly toolchain, resolver 2, and edition-2021 templates. `write_file` skips identical content. **Edit generator templates for durable changes; do not patch ignored generated source as the final fix.** Local editor dependency is derived from the engine package path using `../../ed`.

- Generated `ed/src/main.rs` reads its first argument as the manifest path and calls `arcana_ed::run`.
- Generated `plugins` is a `cdylib` linking the engine, editor, and manifest-selected plugins. It exports Rust functions `arcana_version() -> &'static str`, `arcana_linked(&AtomicBool) -> bool`, and `arcana_plugins() -> Vec<(Name, ArcanaPlugin)>` under unmangled names.
- Generated `game` statically assembles plugins and calls `arcana::game::run`. This runtime entry is absent from the current facade; its template also calls non-const plugin factories in a const array. Treat standalone game generation as unfinished.
- `new_plugin_crate` creates a package with an Arcana dependency. Its starter emits the facade proc macro `arcana::declare_plugin!()`, which generates a package-qualified registry so multiple generated plugins can coexist in one aggregate `cdylib`.

`engine/project/src/wrapper.rs` runs `cargo +nightly` from the generated workspace:

| Wrapper | Operation / contract |
| --- | --- |
| `run_editor` | `run --package=ed -- <manifest>`; sets `ARCANA_PROFILE` and dynamic-link flags. |
| `build_editor` | `build --package=ed`; dynamic-link flags. |
| `build_plugins` | `build --package=plugins`; dynamic-link flags, piped output, returns `BuildProcess`. |
| `run_game` | `run --package=game --features=arcana/ed`; non-dynamic flags, null stdio; template/API compatibility needs repair. |
| `build_game` | `build --package=game`; non-dynamic flags and piped output. |

Dynamic flags are `-Zshare-generics=off -Cprefer-dynamic=yes`; game flags are `-Zshare-generics=off`. Release adds `--release`. `BuildProcess::finished` polls the child, reports captured stderr on failure, and `artifact` returns the expected platform library path; dropping the process kills it. Output is not continuously drained, so high-output build behavior needs local inspection. `game_bin_path` hardcodes the debug directory even when its caller builds release.

`launcher/src/main.rs` chooses CLI when a subcommand exists, otherwise opens the eframe launcher. The GUI manages engines, recent projects, create/open dialogs, and editor build/run child states. `launcher/src/cli.rs` declares display name `arcn`, but the Cargo binary is `arcana-launcher`. Commands: `init`, `new`, `init-workspace`, `ed`, `new-plugin`, `game`, `cook`. `--arcana` accepts TOML dependency syntax; creation can infer names from directories. `cook` is `unimplemented!()`.

CLI path defaults of `.` for opening/building are inconsistent with `Project::open` requiring a file. Supply an explicit manifest, e.g. `cargo run -p arcana-launcher -- ed example/example.arcana`; this is an entry command, not a claim that all example dependencies/templates currently build. Inspect Clap's help for option syntax rather than assuming a conventional `--release` switch.

`launcher/src/lib.rs::Start` loads `dirs::config_local_dir()/Arcana/config.toml` plus `ARCANA_` environment settings. Configuration contains recent projects, engine dependencies, and plugin dependencies; Figa appends vectors. Engines sort/deduplicate; the CLI chooses the first configured engine or the launcher package version. Mutation helpers persist settings; recent projects iterate newest first.

## Plugin registration and dynamic-library contracts

`engine/plugin/src/lib.rs::ArcanaPlugin` owns source location, dependencies, initialization functions, descriptor vectors, and hub-registration callbacks. `PluginsHub` owns ID-keyed maps of boxed systems, input filters, jobs, and importers, plus `Stid`-keyed component descriptors. Repeated component IDs panic before replacing an entry; the other registries overwrite repeated IDs. `ArcanaPlugin::init(world, hub)` populates component descriptors, executes hub-registration callbacks, then runs world initialization functions; dependency ordering is the editor loader's responsibility.

`engine/plugin/src/component.rs::ComponentDesc` registers an opt-in `Component + Reflect + HasStid` type. Its stable ID comes only from `T::stid()`. The descriptor carries its display name, model, optional source location and initial-value factory, and erased component operations. `new` supplies a factory; `without_default` requires the caller to provide explicit component data. `initial_value` returns `Option<Value>`. `ArcanaPlugin::components()` supplies metadata before world initialization; active descriptors are available in `PluginsHub.components`. Registration requires neither `Clone` nor `Send`/`Sync`, and downstream plugins can use the facade's `arcana::model` and `arcana::plugin` reexports without adding dependencies.

Component operations take exclusive access to the world. `read` produces a `Value`; `apply` delegates to the existing component's `Reflect::apply`; `insert` reconstructs from a `Value` and performs ECS insertion/replacement; `remove` uses ECS drop semantics and hooks. Missing entities/components and invalid values are reported as errors; removing an absent component is idempotent. Supplied defaults come from a `fn() -> Value` factory and must be decodable by the component. Descriptors and their clones contain plugin function pointers, so their users must retain the corresponding plugin library guard. Scene membership and lifetime are owned by the editor; entity-reference remapping and persistence migrations are not supplied by these descriptors.

`ComponentDesc::with_add_callback` supplies an optional initializer for interactive addition. The editor calls `initialize_added` after committing a new component and its authored membership. The callback may insert missing companion components and mark those additions in `arcana_plugin::SceneComponents`; it must not replace existing components or despawn the entity. Plain descriptor insertion and snapshot reconstruction do not run this callback, so restoring a scene does not recreate deliberately removed companions.

`ArcanaPlugin::add_scene_init` registers authored defaults separately from ordinary world initialization. `seed_scene` invokes those callbacks; `init` only registers descriptors, fills the hub, and runs ordinary initialization. The editor tracks seeded plugin names across accepted reloads, including when all authored entities are deleted. Play initializes runtime resources and restores the authored snapshot without seeding defaults. `SceneComponents` lives in `engine/plugin/src/scene.rs`, exposes explicit component stable-ID membership, and offers `with::<T>()` for plugin-authored seed entities.

`SystemInfo`, `FilterInfo`, `JobInfo`, and `ImporterInfo` carry stable ID, display name, and source `Location`; job/importer metadata also carries the descriptor used by editor configuration. Registration metadata and live instances have separate owners: use metadata to populate editor UI, hub instances to execute.

Two declaration mechanisms coexist:

- The runtime declarative `declare_plugin!` in `engine/plugin` generates an `arcana_plugin` module and fixed `ARCANA_PLUGIN_REGISTRY`.
- The facade's proc macro `arcana::declare_plugin!` in `engine/proc/src/plugin.rs` generates an `arcana_plugin` module plus a crate-specific `ARCANA_PLUGIN_REGISTRY_<package_with_underscores>`. This is the declaration used by `plugins/dummy`.

Linkme distributed slices collect contributions. `plugin_ctor_add!` requires the syntax **`registry @ plugin => ...`**. Do not interchange the two registry mechanisms or assume compiling the proc-macro crate validates its generated code.

| Macro | Input and current contract |
| --- | --- |
| `#[system]`, `#[filter]` | Plain function, no attribute arguments. Generate local name-based ID, source location and conversion callback into the crate-specific registry. Current dummy demonstrates both. |
| `#[component]` | Safe synchronous nongeneric zero-argument factory with an explicit component return type; no attribute arguments. Registers that type using `HasStid`, the function name and source location, and a generated `Reflect::to_value` factory adapter. Requires the facade's `declare_plugin!` registry. |
| `#[init]` | Plain function; registers an init callback through the crate-specific plugin registry. |
| `#[codex]` | Plain function; attempts to add an init callback, not a separate scripting layer. Its expansion omits the registry argument required by `plugin_ctor_add!`. |
| `#[job]` | Attribute belongs on a trait **impl for a path type**, not on a struct. Expects constructor/descriptor methods and registers through the crate-specific plugin registry. |
| `#[importer]` | Attribute belongs on an `Importer` **impl for a path type** implementing `Default`. Uses the crate-specific plugin registry, constructs through `Default`, and supplies `ImporterInfo.name` and `.desc` from `Importer::desc()`. |
| `Component`, `Relation` derives | Delegate to `edict-proc-lib` with the `arcana::ecs` path. |
| `HasStid`, `has_stid!` | Generate stable type identity. Nonzero integer literals specify exact IDs. Supported non-integer literals are hashed by directly calling `proc/src/literal_hash.rs` during expansion and emitted as numeric literals; other const expressions are evaluated in the consumer and hashed at runtime. Hashed IDs have the high bit set. Derive syntax accepts `#[stid = literal]` and `#[stid(expression)]`; function syntax accepts `has_stid!(Type = expression @ id_crate_path)`. Omitted IDs hash type syntax/shape in the proc macro. Generic derives combine the base ID with type-parameter `HasStid` values; const parameters are included only when explicitly referenced by the expression. |
| `arcana_hash::stable_hash!` | Computes the hash of a supported literal's decoded value on the build host during proc-macro expansion and emits a `Hash64` constant. ### Reload path and ownership

`ed/src/plugins/manager.rs::PluginsManager` owns the build, pending/linked/updated containers, loader, profile, and failure state. On initial tick it builds the project plugin library. Successful build -> load -> verify manifest plugins -> pending -> linked -> update notification. Failure retains the linked version; an initial failure suppresses automatic retries until a user-triggered build. Missing plugin dependencies can be added to the project and trigger regeneration/rebuild.

`ed/src/plugins/container.rs::Loader::load` hashes a library, copies it to a hash-suffixed sibling path, then loads that copy. It checks the three generated exports, engine version, and shared-instance identity; sorts plugins dependency-first; and detects missing/circular dependencies. The runtime's `GLOBAL_LINK_CHECK` guard requires both the same `AtomicBool` address and an activated flag. `set_running_arcana_instance` is called once when starting the editor.

This is a **Rust ABI/shared-runtime protocol**, not a stable C ABI. Existing checks do not prove arbitrary separately compiled libraries ABI-compatible; the loader source explicitly notes the unsoundness risk.

`Plugins` clones retain an `Arc<Loaded>` and active-name set (which can exclude enabled plugins with inactive dependencies). `Loaded` drops metadata before the library and temp-file guard. Any consumer keeping plugin callbacks/trait objects must retain the corresponding `Plugins` until those objects are dropped. `Loader.loaded` holds strong cached Arcs without eviction, so old code versions remain loaded until the loader is dropped; reload does not immediately unload them.

Enable/disable can refresh the active container without recompilation. A plugin becomes active only if explicitly enabled **and** all dependencies are already active; enabling a dependent does not automatically enable its prerequisites.

## Editor lifecycle, simulation, and persistence

`ed/src/lib.rs::run` calls `_run`, which marks the running engine instance, loads the editor project, builds the winit user-event loop, constructs `App`, and calls `run_app`. Errors returned from `_run` are printed. Windows allows event-loop creation on any thread. `init_mev` chooses device index 0/queue 0 with surface support and enables available buffer-mapping and BC texture-compression features for JKLI uploads.

`ed/src/app.rs::App` owns one `arcana::gpu::Gpu`, project, UI, asset store, one shared `Simulation`, clipboard, clocks, preferences/IDE, plugin/system managers, windows, errors, and toasts. `Gpu` groups the device, submission queue, JKL uploader and mev `Cvt`; asset builders borrow this same object. All Simulation tools view and control the shared runtime. Drop order is intentional: the GPU queue precedes views, and `AppView::drop` drops the surface before its window. App teardown flushes cached asset commands, submits a checkpoint and waits for GPU completion. The simulation retains its plugin library guard until all world, hub, flow, and view/work-graph state has been dropped.

Event flow:

1. Startup restores windows, layouts, and saved tools. Suspend saves state and releases native windows while retaining live tools and in-memory layouts; resume recreates windows using those same tool attachments.
2. New events advance the clock and execute due 120 Hz app ticks, then set `WaitUntil` for the next tick.
3. App tick polls plugin build/load. A plugin update refreshes shared managers, clears simulation textures, and initializes the shared simulation from the active plugins. The shared simulation ticks once, then every live tool updates, followed by deferred requests and toasts.
4. Window input is offered to tools attached and visible in that window, then egui. Detached or hidden tools keep receiving background updates but do not receive view input.
5. A visible Simulation tool renders its selected view during its UI call. App rendering acquires the window surface and draws the editor UI using those textures. Acquisition failure logs and clears the surface.
6. Exit saves state and kills registered child processes.

`ed/src/tool.rs` defines `Tool`, `ToolTemplate`, `Toolbox`, the materialized `Tools` container, and `View`. `App` owns the toolbox and live tools globally across editor windows. A view contains only its tool ID; each container entry owns a `Box<dyn Tool>` and attachment/visibility/persistence metadata. Project, the shared simulation, and plugin/system managers are services supplied through `ToolContext` on each call. `SimulationWidget` implements `Tool`; `SimulationTemplate` registers it under `simulation`. `Tool::close` receives the shared simulation and user textures so tools can release their owned views before dropping.

Templates create independent tool instances. The live-tools selector focuses an existing attachment across editor windows and dock surfaces or opens a view for a detached tool. Closing an attachment destroys its tool; explicitly detaching retains it without a view. Only one view may attach to a tool. `Tool::update` runs once per app tick for every live tool, including hidden and detached tools; `Tool::ui` runs when visible. Context requests for child creation and view operations are deferred until callbacks finish, so newly created children first update on the next tick. Arbitrary boxed child tools can be session-only.

`App` retains `FilterManager` and `RenderManager`. The toolbox registers Plugins, Systems, Filters, Render, Simulation, and Assets templates; Scene Editor and Inspector are not registered tools.

The launcher panel below the main menu displays large Phosphor glyph buttons supplied by `ToolTemplate::glyph`, with hover descriptions supplied by `ToolTemplate::description`. Its default selection includes every built-in template. Left-click focuses the first existing instance of that template, including detached instances, or creates one when none exists. Right-click lists all instances, offers `+` to create another, and permits removing the template from the panel. The narrow arrow menu lists only templates absent from the panel and adds the selected template. Selection is shared across editor windows and saved with the project editor layout; an absent selection field uses defaults, while an explicitly empty list stays empty.

`ed/src/scene_editor.rs::SceneEditor` owns the authored ECS world, component registry, shared entity-ID source, and accepted plugin library guard. `arcana::plugin::SceneComponents` marks an authored entity and lists the `Stid`s of its authored components. Empty marked entities are retained; generated components absent from the list are excluded from snapshots. `SceneEditorWidget` is a tool with editor/renderer selection, an authored-world render view, and an optional owned simulation. Play snapshots the shared scene and creates an independent runtime; Stop releases its textures and drops that runtime. Authoring edits through another tool do not alter an already running simulation. `ed/src/scene_tree.rs` uses `egui_ltreeview` for hierarchy selection and drag reparenting. Selection is shared with viewport picking. `Renderer` is a built-in reflected component in both scene and simulation hubs. Adding it requires selecting an existing render graph; no graph is fabricated as a default. Its owning entity may carry camera data or any other components required by jobs. The scene tracks renderer addition order independently of entity IDs and preserves that order across plugin reload. Scene plugin reload is transactional: capture with the old descriptors, initialize a fresh world/hub with the candidate plugins, restore authored values, then commit. Failure retains the accepted scene and managers. Success advances the accepted plugin revision; playing widgets observe it during their next update and stop before ticking against changed managers.

`ed/src/entity_ids.rs::EntityIds` creates all editor and simulation worlds from one shared pool in `1..2^63`. Fresh leases contain up to `2^32` IDs; reused leases contain at least `2^24`, preserving a large prefetched reservation range at mutable allocation/flush boundaries. Issued IDs are never recycled, so copying authored IDs between worlds cannot collide with subsequent fresh allocation. Returned unissued ranges containing at least `2^24` IDs are retained and coalesced; smaller fragments are discarded. The sibling edict `IdRangeAllocator` has an unsafe release hook; `IdAllocator` returns its unused ranges on drop after `EntitySet` accounts for pending reservations. Pending reservations count as issued even when never materialized. Saved-scene ID reservation across editor sessions remains part of future file-loading work.

### Simulation and schedule

`ed/src/simulation.rs::Simulation` owns an edict `World`, `PluginsHub`, `Flows`, fixed ticker (20 Hz), variable limiter (120 Hz), rate/clock state, plugin lifetime guard, schedule, and views. `init_world` sets up flow support and inserts zero `Tick`.

Simulation initialization runs active plugins dependency-first. New and rebuilt worlds use `App`'s shared entity-ID source. Plugin updates rebuild the runtime, preserving live view IDs and speed. Reset clears entities/resources, hub/system state, schedules, filters, flows, render caches and registered textures, renderer selections, and input focus, resets tickers/time, then reinitializes active plugins. The plugin guard remains alive throughout cleanup. Runtime state migration and runtime-world persistence are not implemented.

Simulation tick refreshes the schedule, scales elapsed time by simulation rate, runs Fix systems per fixed tick and Var systems when the variable limiter ticks, wakes/executes flows, then applies deferred/received actions. A zero rate pauses time, systems, flows, and deferred/received action execution; input and rendering remain available. `Tick` is inserted for the relevant step. Systems execute sequentially through `Schedule::run`; action buffers are applied after the category.

`ed/src/systems.rs::SystemGraph` serializes an egui-snarl graph of `SystemNode`s. Nodes store system ID, name, plugin, enabled flag and Fix/Var category; runtime availability and source location are skipped. `SystemManager::update_plugins` refreshes available descriptors and marks the graph modified. Newly offered systems default to disabled/Fix. Changing category removes that node's links. UI edits persist via project sync. Source links go through the selected IDE.

`order_systems` waits for predecessors and includes only active/enabled IDs. `SystemManager::update_plugins` clears inactive descriptors, and `update_schedule` advances the simulation's schedule revision. Remaining source-level limits: no cycle-termination guard and hub lookup unwraps.

## Editor asset ingestion and storage

This layer imports source files into artifacts; the engine asset cache separately loads/builds typed runtime assets.

`ed/src/assets/store.rs::AssetStore` owns one shared `AssetDatabase`, a time-based ID generator, importer descriptor map, `AssetRegistry`, and `Fetcher`. Source files may live under `<project>/assets` or outside that directory; its root `tmp`, `registry`, `sources`, and `.external` directories are reserved for internal storage. Sources are imported in place without copying. Built-in importer descriptors are available at construction and retained when plugin updates refresh descriptor selection; importer instances live in the simulation's `PluginsHub.importers`, with plugin-owned instances protected by its library guard. `find_importers` filters target plus optional format/extension. Imports use the engine's synchronous `Importer` interface, preserving existing per-source/target IDs and advancing persisted artifact versions on successful reimport. Additional source stamps and dependency IDs are recorded in metadata. Required inputs are resolved relative to the importing source; retries and dependency cycles are bounded. Artifact publication follows blob staging, metadata replacement, then registry publication; an unsuccessful reimport retains its accepted metadata and registry mapping.

`assets/fetcher.rs::Fetcher` handles local file URLs and data URLs; data bytes are cached under SHA-256-derived names. Other schemes are unsupported. Its source mapping is memory-only.

`assets/meta.rs::SourceMeta` handles sibling `<source>.arc` JSON files for internal sources. External sources use `<project>/assets/.external/<full-SHA256>.arc`, hashing the canonical absolute source path encoded bytes; external metadata additionally stores the absolute `source` path. Project-aware loading validates that source identity and filename agree and rejects a linked `.external` directory. Internal metadata derives source identity from its sibling path and ignores any stored `source` field. The object contains `assets` (target entries) and `tags` (source-level strings); legacy files containing only an asset-entry array remain readable. Target entries carry `AssetMeta`: ID, target, blob, format, dependencies, source modification stamps, configuration, importer identity, and monotonic artifact version. Tags are trimmed, lowercased, sorted, and deduplicated; unimported source files can have tags. Metadata writes use a synchronized sibling temporary file followed by replacement. Source timestamps determine freshness, while artifact versions distinguish configuration changes and imports within the same second. `assets/registry.rs::AssetRegistry` maps `AssetId` to blob/version behind `Arc`/mutex and implements engine `Loader`; synchronous reads are wrapped in ready futures. Catalog startup and refresh reconstruct the mappings from persisted source metadata.

`ed/src/blobs.rs::Blobs` stores SHA-256-deduplicated bytes. File names start with short hash prefixes (eight characters) and extend/compare on collisions; `BlobId` combines hash/index. Bytes, files, and temporary-file moves are insertion paths.

`assets/database.rs::AssetDatabase` caches project-relative source files and directories, including unimported files, plus absolute external sources recovered from `.external` metadata. Explicit refresh rebuilds the catalog; it does not scan every frame or watch source changes. Internal storage and `.arc` sidecars are hidden, and linked paths are excluded. Import selection accepts existing internal and external files, rejecting missing files, directories, `.arc` sources and reserved project storage without copying files. Relative dependency paths resolve against the actual source parent and can reach external files. External entries appear in root browsing and searches, retain tags/configuration/IDs across reopening, and restore existing artifact mappings even when their source is missing; source existence is required on import. Search combines case-insensitive filename substring matching, optional ranked fuzzy subsequence matching, and exact all-tags filtering. Search can cover the current folder or its descendants; deterministic ordering resolves equal scores. Corrupt metadata is surfaced as a catalog warning. External metadata identity is loaded without canonicalizing its possibly missing source.

`assets/browser.rs::AssetBrowser` implements the registered `Assets` tool (`assets` template key). `ToolContext` supplies the shared store, so multiple tools observe the same catalog and tags. The tool browses folders, searches names and tags, edits source tags, configures built-in and active plugin importers through `ValueProbe`, imports existing internal or external source files, and reimports catalog selections. The file picker starts in the current asset folder; external entries display their absolute source path and external status. Source validity is checked before opening configuration and again before importing; configuration and tags use project-aware metadata locations. Dialogs retain importer IDs and configuration values rather than plugin-owned references. Tool snapshots retain browsing/search state; file and import dialogs are transient. ## Runtime engine contracts

### Facade and ECS

`engine/arcana/src/lib.rs` is a facade, not an engine main loop. It reexports subsystem crates, interned names/macros, proc macros, and selected dependencies (including `athena`, `mev`, `gametime`, and `tokio`). `version`, `type_id`, and `static_assert!` are small helpers. `render.rs::Renderer { graph: RenderGraphId }` is an ECS component; `CurrentRenderer { entity: EntityId }` tells rendering jobs which renderer entity supplies camera/other data.

`engine/ecs/src/lib.rs` reexports edict and adds `SystemId` plus Arcana-aware component/relation derive paths. Use the reexported API for Arcana plugin code. The ECS implementation lives in sibling `edict`; changes to borrowing/query/scheduling internals require its own source/API reference.

`engine/ecs/src/flow.rs` adds `sleep(duration, FlowWorld)` and `sleep_until(deadline, FlowWorld)` to edict flows. These use ECS `Tick`, **not wall-clock/Tokio time**. Host code must call `init_flows`, supply clock steps, call `wake_flows`, and separately execute the edict `Flows` object. Timers are a nearest-deadline binary heap; waking a flow does not itself run it. Zero-duration sleep returns immediately.

`engine/unfold/src/lib.rs::Unfold` describes expanding a compact component using declared component and resource queries plus deferred `ActionEncoder`. Implementations supply `type Query: QueryArg`, `type Resources: ResourceQuery`, and `unfold(&self, QueryItem<Self::Query>, ResourceItem<'_, Self::Resources>, ActionEncoder) -> bool`. Resource-free implementations use `Resources = ()`. The sealed resource query in `src/resource.rs` supports shared/mutable static reference declarations, their optional forms, and tuples through twelve elements. Existing ECS `Res`/`ResMut` guards retain borrows once per typed pass; callbacks receive short-lived ordinary references. Missing required resources leave the component-query checkpoint untouched, so work retries when the resource appears. Optional missing resources are passed as `None`. Conflicting component/resource borrows panic through ECS borrow checks. Component-query `before` hooks run while the requested resource guards are held and cannot make conflicting resource borrows.

`register_unfold<U>` deduplicates types and queues systems; `unfold_system` absorbs registrations, runs typed passes exclusively in registration order, and applies action buffers after all guards and component-query checkpoints finish. The typed system visits `Modified<Alt<U>>`, retaining its query state through `QueryArg::new/before/after`. Success leaves the component's epoch alone; `false` defers a fresh modification stamp until after the query checkpoints its epoch, so expansion retries on the next run. Resource changes alone do not re-run successful components. No unfolding derive macro is exported; implementations and registration are explicit.

### Typed assets: load is not build

`engine/assets/src/asset.rs` defines:

- `AssetVersion: HasStid`: opaque code/recompilation version.
- `Asset: AssetVersion + Send + Sync + Clone`: associated `Loaded: Any + Send + Sync`, async `load(Box<[u8]>, &Assets)` for decoding/dependency resolution, synchronous `build(Loaded, &mut AssetBuilder)` for runtime/GPU construction.
- `loader.rs::Loader: Send + Sync`: obtains `AssetData { bytes: Box<[u8]>, version: u64 }` by ID; required `update(id, version)` method returning optional newer data. The cache does not call `update`; the editor observes project registry revisions and explicitly invalidates it.

`assets.rs::Assets` is a cloneable shared cache keyed by stable type ID, with 97 mutex shards per type keyed by asset ID. Requests follow this state machine:

```text
missing --request/tokio::spawn--> Loading --A::load--> Loaded
                                      |                |
                                      v                | explicit build queue drain
                                    Error              v
                                                   Building -> Ready / Error
```

`get<A>` returns `Poll<Result<A, Error>>`, starts a missing request but does not register a waker; retry polling is the caller's responsibility. `poll<A>` registers/deduplicates a waker. Ready assets clone; errors are cached. `load_from_any` tries loaders in order, falling through only on NotFound. Async decoding can request dependencies from the same `Assets`.

An entered Tokio runtime is required for missing requests; absence returns an error without publishing a stuck Loading entry. Loaded values enter a FlipQueue and cannot become Ready until the host drains it through `AssetBuildContext::build_assets(assets, gpu)` / `Assets::build_assets`. Queue draining collects requests before invoking asset builders. `AssetBuilder` borrows the shared `Gpu` and exposes a tracked command encoder; `device()` provides device access and `encoder()` marks that submission is needed. It has no auxiliary typemap. `AssetBuildContext` reuses an encoder and submits only if mutated. Its explicit `flush(gpu)` submits any cached encoder before queue shutdown; it requires the originating GPU queue, does not build pending assets or wait for completion, and is a no-op without a cached encoder. Do not await an asset indefinitely while failing to drive its build queue.

There is no implemented eviction/memory accounting or automatic filesystem source watching despite broader module documentation. `Assets::invalidate_all` invalidates shared cache state across all handle clones, aborts its loading tasks, retires typed buckets, discards queued builds, and wakes Loading/Loaded/Building waiters after releasing locks. Generation-tagged build requests cannot populate retired buckets or destroy unrelated states. `drop_all_except` retains only matching stable-type-ID/version entries. Concrete TypeId and asset version are checked before typed casts. Plugin load, build, clone, drop, and wake callbacks execute outside cache locks; Ready entries retain an Arc while cloning outside the lock. `AssetError` is a separate cloneable Arc-backed error with type checks, convertible to the universal engine error. Active `AssetId` comes from the `make_uid!` invocation in `assets/src/lib.rs`; `assets/src/id.rs` is not declared.

Decode failures publish the cached error, release the cache lock and wake registered waiters, allowing dependent asset loads to terminate. Building state prevents duplicate builds and supports reentrant asset requests. Invalidation can retire a build while its synchronous callback runs; that callback's result is discarded instead of being republished. Hosts must retain defining plugin libraries until plugin futures and cached values have been destroyed.

`engine/arcana/src/assets.rs` reexports the standalone asset API and composes it with ECS/Unfold without adding ECS dependencies to `arcana-assets`. `arcana::assets::AssetRef<A>` contains a public `AssetId` and a phantom asset type; `A` must implement both `Asset` and `Component`. Register `AssetRef<A>` with `register_unfold`, insert `AssetRef::<A>::new(id)` on the entity, and drive `unfold_system`. Its optional `Assets` resource query retries missing resources and Pending loads. Success installs `A` on the same entity; terminal failure installs `AssetLoadError<A> { id, error }` and stops retrying. The marker remains in both cases. Changing its ID or reinserting it requests another load and clears stale owned results. Dropping/replacing the marker removes its owned `A` and typed error through ECS hooks; `World::remove` extracts without hooks and therefore retains installed results. Cache invalidation alone does not re-unfold successful markers; reinsert or mutate them to request refreshed values.

### Distance-field fonts

`plugins/msdf-font` is a workspace plugin. `FontImporter` produces a versioned font artifact from selected TTF characters using `bymsdfgen-core` and direct `ttf-parser` parsing with a private outline adapter. `engine/work-graph/src/job.rs::Job` has static name/descriptor/constructor, mutable per-frame `plan(Planner, &mut World)` and `exec(Exec, &mut World)`. `JobsSet` maps `JobId` to boxed jobs. Although high-level design calls jobs conceptually read-only, the actual API grants mutable world access, including caching components.

`JobDesc` declares named model parameters and typed reads/updates/creates. Update is both an input and output. Public descriptor pin numbering is **inputs: updates -> reads -> params; outputs: updates -> creates**. Use the descriptor index/type helpers rather than duplicating offsets.

`graph.rs::WorkGraph::new(jobs, edges)` computes a dependencies-first plan and shared `TargetId`s across wires/update chains, returning `Cycle` for cyclic input. Invalid endpoint/index/type assumptions often panic; it is not a general validated graph interchange format.

`set_sink<T>(pin, external_target, info)` installs an externally supplied output and makes its producer a work root. Per run:

1. Clear selected jobs and seed selection from sinks.
2. Walk the plan backward: consumers express requirements and select upstream producers.
3. Walk selected jobs forward: execute jobs, invoke hooks, finish and submit accumulated encoders.

Execution is serial, not a parallel scheduler. Missing `JobId`s in the live set are skipped. Hooks do not select work and capture the target ID at registration.

`Planner::create/update/read<T>` consume their respective descriptor streams **in declaration order**, asserting stable target type IDs. Reads supply target requirements; creates merge consumer requirements and allocate; updates propagate demand only when target information exists. `param(name)` expects a supplied parameter and can panic when absent.

`Planner::create_with_info` lets a producer adjust a demanded output description before allocation. Its closure must retain required usage flags. Undemanded outputs remain unallocated; an external target whose description differs from the adjusted result is rejected with an assertion. Pixie uses this to select its own image resolution while retaining consumer usage requirements.

`Exec::create/update/read<T>` likewise consume declaration-order streams and return `Option<&T>` when resources may be disconnected/unavailable. `new_encoder()` allocates an arena-backed encoder submitted automatically by the graph. Jobs should not assume every declared resource is demanded in a frame.

`target.rs::Target: HasStid` defines comparable `Info`, allocation, and optional requirement merging. `TargetHub` erases runtime target types with an unsafe map boundary. `TargetData` prioritizes external targets; internal allocation is reused while information stays equal, otherwise recreated. `Image2D` requires equal extent/format and unions usage; `SampledImage2D` requires equal format, grows extent per axis, and unions usage. Allocations have one mip level.

Known source inconsistencies to inspect for graph changes:

- `graph.rs` offsets read dependencies by updates+creates while `JobDesc::read_idx` uses updates only. Inspect editor wiring and descriptor helpers together when fixing pin layout.
- `TargetData::plan_read` ignores the boolean failure result from `merge_info`, so conflicting readers are not reported there.
- `job_desc!` / `add_job_desc!` reference `$crate::work` while the facade exposes `work_graph`; macro expansion needs its own validation.

### Input normalization

`engine/input/src/lib.rs::Input` wraps `ViewInput`/`DeviceInput`. Window conversion supports resize/scale, keyboard/modifiers, cursor and mouse input and rejects unsupported winit events. Coordinates become f32. `DeviceId` wraps native or emulated identity; `DeviceInput` is empty and raw device event conversion currently rejects all events.

`InputFilter::filter(&mut World, &Input) -> bool` returns true when consumed. `IntoInputFilter` accepts closures with or without world access. `InputFunnel` holds ordered boxed filters, stops at the first true, and itself implements the filter trait. The editor persists filter IDs/order separately and dispatches through its plugin hub.

### Models and graphics assets

`engine/model/src/model.rs::Model` represents Unit, Bool, Int, Float, String, Color, TimeSpan, vectors/matrices, Option, Array (optional element/length), Map, Tuple, Record, and Enum. There are no EntityId/AssetId variants despite broader prose. Defaults include numeric zero, alpha-one colors, zero vectors, identity matrices, absent options, empty dynamic collections, recursively defaulted fixed fields, and first enum variant (or Unit if empty).

`value.rs::Value` stores corresponding data using i64/f64, SmolStr, Athena f64 math, palette colors, boxed options/enums, arrays, string-keyed maps, and `Reference(Ident, u64)`. `Value::model()` returns shallow collection schemas rather than inferring all nested types. `lib.rs::Reflect: Sized` supplies `model`, `to_value`, and checked `from_value -> Result<Self, ValueError>`. Its default `clone_from_value` clones the input value before decoding; default `apply` decodes before replacement and leaves the receiver unchanged on error. Overrides must preserve that error contract. `Reflect` requires no `Clone`, thread-safety, lifetime, or serde bounds. Implementations cover unit, bool, i64/f64, SmolStr, colors, TimeSpan, Athena f64 math, Option, Vec, and edict `EntityId`. Inactive codex getters add their own `Clone + 'static` bounds.

`arcana-id` depends on `arcana-model` and its ID macros emit explicit `Reflect` implementations; `BaseId` implements reflection directly. `arcana-model` depends on edict for `EntityId` reflection and has no dependency on `arcana-id`. Reference domains use the ID type's simple name (for example `RenderGraphId` or `EntityId`), not a globally unique Rust type identity. Decoding checks the domain and rejects zero while preserving every other `u64` value. `Model::Reference` defaults to a tagged zero as an unbound editor value. `Renderer` reflects transparently as its graph reference and has an explicit stable component identity.

`serialize_to_value` / `ValueSerializer` convert serde values into this model; `Value` also implements Deserializer. Unit enum variants retain their identifier as `Value::Enum` with a Unit payload, allowing typed configuration enums to round-trip and use Enum editor controls. Newtype enum variants serialize their payload without retaining the variant name; complete enum-variant serialization is not supplied. Bytes map to the custom base58 string representation. Derived Serialize of `Value` itself emits the tagged Value representation: it is not interchangeable with typed-value conversion. `deserialize_bytes` handles strings and reaches `todo!()` for other variants. Model changes affect job/importer configurations and editor probes.

`engine/graphics/src/texture.rs::Texture` wraps `mev::Image2D` and is a cloneable component/stable-ID asset (version 0). `LoadedTexture` retains validated JKLI bytes. Loading accepts one nonempty plain 2D image level, with RGB8 or BC1 using ANS/LZ77+ANS, or R8, RG8 and RGBA8 using ANS. R8 and RG8 build native `R8Unorm` and `Rg8Unorm` sampled images. Packed R8 tile widths must be multiples of four and RG8 tile widths multiples of two; invalid widths are rejected before GPU decoding. Unsupported dimensions, mip counts and format/compression pairs return asset errors. Building uses the shared GPU's JKL uploader, records a compute-to-transfer barrier, creates and copies the sampled image, and records a transfer-to-shader barrier. Native uploader use requires buffer mapping; BC1 additionally requires BC compression enabled on the device. `graphics/src/bu.rs` is undeclared draft code.

## Foundation utilities and identity rules

| Crate / implementation | Contract and change-sensitive details |
| --- | --- |
| `alloc/src/arena.rs::Arena<T>` | `put(&self, T) -> &mut T` uses stable-address interior allocation. Send for Send T, not Sync. `reset` drops values; `drain` yields insertion order and reuses the final buffer. Work graph stores encoders here. Raw allocation/drop code requires local safety review when changed. |
| `intern/src/intern.rs` | Process-lifetime leaked/deduplicated strings, 17 RwLock shards. `Name`/`Ident` are Copy wrappers with serde/formatting helpers. Avoid interning unbounded arbitrary content: storage is never freed. |
| `intern/src/{name,ident}.rs` | Name: nonempty, no control characters. Ident: Unicode XID start/continue; dynamic validation rejects leading underscore. Static helper paths assert ASCII. Keep literal/dynamic validation differences in mind. |
| `id/src/lib.rs` | Strong nonzero-u64 ID macros. UID serde is numeric; display/parse uses custom base58 of little-endian bytes. Some visitor error text says hex but does not define the actual format. `static_id!`, hash IDs, and module-sensitive IDs affect persisted identity. |
| `id/src/{seqgen,uidgen}.rs` | `SeqIdGen` gives local IDs. `TimeUidGen`: 34-bit seconds, 10-bit counter, 20-bit generator; waits past construction second and blocks on per-second wrap. It is not an unlimited-throughput allocator. |
| `id/src/stid.rs` | Stable type identity via `HasStid`. The hasher is stable; changing an expression value type's `Hash` implementation may change its ID. Exact numeric IDs do not depend on hashing. TimeSpan and chrono TimeDelta currently share `0x41`: inspect this collision before relying on mixed-type erased storage. |
| `hash/src/stable.rs` | Runtime hashing and `proc/src/literal_hash.rs` use Foldhash `FixedState::with_seed(17)` with its nightly feature; parity tests cover the literal macro and runtime function. Proc-macro syntax hashing in `proc/src/stable_hasher.rs` uses AHash seeds `(1,2,3,4)`. Do not change either algorithm or seed without considering persisted IDs. |
| `hash/src/lib.rs`, `sha2.rs` | Hash64/128/256/512 native-endian typed/byte views; human-readable serde uses custom base58, binary serde bytes. SHA256/512 helpers for bytes/readers/files. |
| `hash/src/noop.rs::NoHasher` | Integer writes only (u128 truncated); byte-slice `write` is unimplemented. `NoHashMap` is unsuitable for arbitrary string/compound keys. |
| `base-encoding/src/base58.rs` | **Custom block encoding**, not conventional whole-number Bitcoin Base58: each two little-endian input bytes gives three characters, with a special one-byte tail. Reuses the Bitcoin alphabet only. Do not substitute a generic base58 library for persisted values. |
| `base-encoding/src/lib.rs` | no_std+alloc encode/decode traits; default `std` feature adds I/O/error support. Contains the repository's explicit unit tests. |
| `num2name/src/lib.rs` | Deterministic adjective/color/noun display name from u16 (5/5/6 bits), hash or ID. Not a unique identifier. |
| `io/src/buffer.rs` | Tracks consumed, filled, unfilled, and uninitialized storage. Borrowed/array/growable implementations. Initialize bytes before exposing to Read and respect writable-count limits. |
| `io/src/bufread.rs` | `BufferRead` implements Read/BufRead and `fill_buf(min)`, retrying Interrupted and stopping at minimum/EOF/capacity. |
| `io/src/fs.rs` | Content comparison after length checks. In `files_eq`, the second-reader branch increments len1 rather than len2; revisit before relying on that helper for a changed workflow. |
| `error/src/lib.rs` | Universal boxed Error stores Arc Send+Sync error plus captured backtrace, preserves already-wrapped Error, supports context/source chains/downcasting, extension traits and `error!`/`fail!`. |

Stable IDs, custom encodings, and type erasure connect persisted graphs, plugin exports, asset caches, and target maps. An identity change is not just a local rename. Reopen the producer and consuming erased/persisted boundary before altering ID derivation, explicit IDs, serialization, or hashing.
